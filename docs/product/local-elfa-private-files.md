# Local Elfa private-file dependencies

Source-only, default disabled. This packet does not activate Elfa, authenticate a harness, change a route or duplicate the existing reservation/admission engine. Only trusted startup code may construct these objects; never expose their generic filesystem helpers as tools.

`createLocalElfaPrivateFiles({dataFile, configurationFile, credentialFile})` is inert. Readers verify absolute canonical physical paths, same UID, exact 0700 parent directories and 0600 regular single-link files. Descriptor reads use NOFOLLOW/NONBLOCK, a byte ceiling, fatal UTF-8 decoding and before/after path, descriptor, directory, size and timestamp checks. The runtime data bound is native `localInstallation.id` plus SHA-256 of its canonical path; normal atomic data replacement is allowed, installation changes are not.

Configuration is a single atomically replaced JSON object: `{format:'angbao-local-elfa-files@1', revision:0, grant:null, policy:null}` is disabled. Enabled configuration contains the existing exact operator grant and policy together. Grant installation/path and canonical policy digest must match. Grant/policy fields and expiry/rights/entitlement/budget admission remain owned by `local-elfa-operator.mjs` and `headless-elfa-evidence.mjs`. Revision is a nonnegative safe integer; each owner configuration replacement must increase it. A constructed binding pins the entire configuration, including revision, so any change requires explicit reconstruction and new matching consent.

The separate credential object has exactly `{format:'angbao-local-elfa-key@1', keySlot, apiKey}`. `createBinding({repository,fetchImpl,now})` reads it only after enabled configuration, keeps it inside the existing operator binding and returns only preview/fetchEvidence methods. Each context read rechecks the credential digest and complete configuration. Rotation/revocation/configuration change fails closed. Never log dependency objects, input files or credentials. Raw filesystem/JSON exceptions are replaced with bounded messages.

`privateJsonTransaction(file, work)` is an internal synchronous cooperative single-host primitive: exclusive directory lock, bounded read, original-value compare, exclusive private temp, fsync, rename and parent fsync. A failed transaction leaves a lock for explicit operator reconciliation; no automatic retry, lock expiry or stale-lock deletion. A crash after rename may have committed: inspect saved state before an explicit recovery decision. This is not adversarial same-UID shell isolation or protection against undetectable malicious in-place modification. No OS filesystem API here can make that claim.

Existing real credentials and original workspace files must not be inspected by tests. Configuration provisioning remains an explicit owner/integrator action; this module does not create or enable configuration automatically.

## Trusted runtime integration

The explicit owner-local runtime composes this loader, existing consent store and existing service/ledger. `createBinding` additionally exposes trusted `assertCurrent()` returning no data: it invokes the existing pinned configuration/key check synchronously for final dispatch/egress. It is never an MCP tool. No filesystem/key object is returned. The runtime binds descriptor/config/key and private evidence target into its durable disclosure, so changes across invocations require a fresh matching preview/approval.

Consent adds `readStatus({operationId,expectedDigest})` (pure, works for expired/revoked records without refreshing approval) and synchronous `assertApproved`, reused by `guardDispatch` and final egress. SQLite adds owner/key/operation `inspect` plus explicit `readOnly:true` opening without DDL, creation, reserve/settle or hot-journal repair. Missing state is distinguished from unavailable/recovery-required state. See [owner setup and installed flow](local-elfa-operator-handoff.md). A historical private evidence artifact remains separate from research-memory save and never restores provider/financial authority.

Artifact/bootstrap creation uses the primitive's explicit `createOnly:true` option. It atomically links the complete fsynced private temporary file into a previously absent destination and removes only its own temporary link. A file that appears at the final boundary causes refusal rather than rename-overwrite. A post-publication failure retains the recovery lock/evidence. Existing replacement/CAS callers retain their original behavior; no new ledger or silent lock repair exists.
